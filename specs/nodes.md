## 1. 공통 데이터 계약 (Q11)

- 실선 엣지로 흐르는 것 = **아티팩트**: `{ format: 'markdown' | 'json',
  content }` (결정 6). 노드 실행 1회 = 아티팩트 1개(DB 행).
- **다중 입력 = 출처 라벨링된 섹션 규약**: 노드 실행 시 상류
  아티팩트를 `{출처 노드 이름 → 아티팩트}` 맵으로 수집. Agent의 유저
  메시지는 엔진이 자동 합성 — 상류 아티팩트마다 `## 입력: {노드 이름}`
  섹션(마크다운은 본문 그대로, JSON은 코드블록). 프롬프트 템플릿 변수
  (`{{jd}}` 류)는 쓰지 않는다 — 배선 변경이 프롬프트 수정을 요구하면
  레고 컨셉이 깨짐. 입력 순서가 중요하면 엣지 클릭으로 순번 조정.
- **엣지에 포트 타입 없음** — 실행 노드끼리는 자유 연결. 대신 run 시작
  검증에서 의미 제약 체크: Gate 상류에 JSON 출력 노드 필요, Output
  상류에 마크다운 정확히 1개.
- **다중 출력은 Gate만**(pass/fail 2핸들). 나머지는 출력 1개 — 분기하면
  같은 아티팩트가 병렬 복제(결정 4: 분기=병렬).
- **AND-join (Q15)**: 상류 엣지가 여러 개면 전부 완료되어야 실행 시작.
  OR-join은 v1에 없음.
- **노드 실효 config = block_def.config에 오버라이드 필드별 덮어쓰기.**
  `block_def_id=null`이면 `config`가 완결. `name`은 항상 노드 소유 —
  정의 이름 변경이 노드 이름·Gate 조건식을 끌고 가지 않음(schema.md 설계
  원칙 3).

## 2. 에이전트 (Q12)

가장 복잡한 노드. Agent 노드 1회 실행 = Claude Agent SDK `query()` 1회
호출(결정 2). 세션 재사용 없는 단발 호출 — 컨텍스트는 매 실행마다
시스템 프롬프트(역할+장착물) + 합성된 입력 섹션(Q11)으로 재구성.
재현성과 부분 재실행이 단순해진다.

### 속성

| 구분 | 필드 |
| --- | --- |
| 기본 | 이름 · 역할(시스템 프롬프트, `doc:` 포인터 삽입 지원) · 출력 형식(markdown/json) · 장착된 기술/규칙/도구 목록(mounts, 읽기 전용 — 장착은 팔레트에서 드래그) |
| 고급 | 모델 · JSON 스키마 · 갭 인터뷰 모드(멈추고 묻기 / `[확인 필요]` 계속) |

**config.mounts 구조**: `{ blockDefId: string, override?: Partial<BlockDefConfig> }[]`.
각 항목은 기술·규칙·도구 정의를 참조한다. 팔레트에서 기술/규칙/도구를
Agent 카드 위로 드래그해 칩으로 장착. 여러 Agent가 같은 정의를 칩으로
공유 참조 가능.

### 장착물의 SDK 번역

| 장착 | SDK 번역 | 의미 |
| --- | --- | --- |
| 규칙(Rule) | 시스템 프롬프트 뒤에 `## 규칙: {이름}` append | 항상 지킬 제약(톤·수치화 강제 등) |
| 기술(Skill) | `agents` 정의에 스킬 마크다운 주입 — 구현 시 단순하면 시스템 프롬프트 append로 대체 가능(M2 이관 시점에 선택) | "어떻게 하는지"의 방법론. 규칙=제약, 기술=방법 |
| 도구(Tool) | `query()` 허용 tool 목록에 추가 | 실행 중 능동 호출 기능(`get_document` 등) |

### JSON 출력 강제

스키마를 프롬프트에 명시 → 응답 파싱 실패 시 파싱 에러를 피드백으로
**1회 자동 재시도** → 재실패면 노드 실패.

### 갭 인터뷰

- **멈추고 묻기**: 내장 tool `ask_human(question)`을 부여. Agent가
  호출하면 SDK 호출이 대기로 멈춤 → 챗봇 패널에 갭 인터뷰 카드 → 사람
  답변이 tool 결과로 돌아가 계속 진행.
- **`[확인 필요]` 계속**: `ask_human` 없음. 프롬프트 지시로 본문에
  표기만 하고 계속.

## 3. 자료 Input (Q15)

문서 라이브러리에서 문서를 읽어 마크다운 아티팩트로 방출.

- 기본 속성: 문서 참조(document id). 고급: 인라인 텍스트 모드.
- **버전 시맨틱**: run 스냅샷은 그래프 구조만 고정. 문서 내용은 Input
  **실행 시점의 최신 버전**을 읽는다. 재현성은 아티팩트가 담보 —
  방출 아티팩트에 내용 전문 + 문서 버전 번호 기록.

## 4. 완성본 Output (Q15)

상류 마크다운 → 결정론적 코드 변환(LLM 없음, 결정 10) → 자기완결형
HTML 1파일 아티팩트.

- 기본 속성: 템플릿 선택(1~2종). 고급: 파일명 규칙.
- run 시작 검증: **마크다운 상류 정확히 1개**(JSON 상류는 무시,
  0개/2개+면 검증 에러). Gate를 거쳐 초안+비평이 함께 와도 마크다운은
  초안 하나라 자연 충족.
- HTML 아티팩트도 DB 저장 — run 히스토리에서 과거 이력서 재다운로드
  가능. 다운로드 진입점은 [ui.md](ui.md) "최종 이력서 다운로드" 참조.

## 5. 관문 Gate (Q13)

**다중 입력 순수 라우터.** 핵심 설계: Gate는 비평가의 JSON으로
판정하지만 하류에 필요한 건 작성자의 초안 — 그래서 초안과 JSON을 **둘
다 Gate로 배선**하고, Gate는 만들지 않고 흘려보내기만 한다.

- 기본 속성: 조건식. 고급: 실패 라우팅 대상 · 최대 루프 횟수(기본 3).
- **조건식**: LLM 없이 sandboxed 표현식 평가기로(결정 6. `eval` 아님).
  비교·논리 연산과 `.length` 정도의 서브셋. JSON 입력의 필드 참조 —
  JSON 입력 1개면 `score >= 8`, 여럿이면 `비평가.score >= 8` 출처 접두.
- **pass**: 입력 전체를 라벨 유지한 채 그대로 통과. Human은 초안+비평을
  함께 받아 검토 맥락 확보, Output은 마크다운만 취함.
- **fail**: fail 엣지가 가리키는 노드부터 재실행(하류 재구동, 회차
  증가). fail 대상 노드는 재실행 시 **직전 회차의 비평 JSON이 입력에
  자동 포함** — "비평 반영 재작성" 성립 조건.
- **최대 루프 초과**: run을 `gate_failed`로 종료 + 채팅 보고 카드(최종
  점수·사유). "초과 시 Human 폴백"은 v2.

## 6. 내 검토 Human (Q14)

**사람이 판정하는 통과 노드. 출력 = 승인본.**

- 기본 속성: 지시문. 고급: 편집 허용 여부 · 주 입력 지정(마크다운
  입력이 여럿일 때만 — 1개면 자동).
- **행동 2가지**: ① 승인 — 입력 그대로 하류로. ② 편집 후 승인 — 주
  입력을 고친 승인본이 하류로. 편집본은 새 아티팩트(주체=사람)로 저장.
- **반려 버튼 없음** — 상류를 다시 돌리고 싶으면 노드 우클릭 "이
  노드부터 재실행"(ui.md Q8)을 쓴다. Gate fail 라우팅과 역할 중복 방지.
- **대기**: 타임아웃 없음. run은 `waiting_human`으로 DB 기록,
  새로고침·프로세스 재시작에도 복원(결정 8). 챗봇 패널 카드 [승인]과
  중앙 탭 에디터 [승인]은 같은 API의 동일 동작.
- 출력 형태: 입력 전체 통과 + 주 입력만 승인본으로 교체.

## 7. 기술/규칙/도구 — 장착 계층 (Q15, M4 재설계)

실행되지 않고 아티팩트도 없다. Agent 실행 시 §2 번역으로만 존재.

- 기술(Skill)/규칙(Rule) 속성: 이름 + 내용(마크다운 텍스트).
- 도구(Tool) 속성: 내장 카탈로그에서 선택. **v1 카탈로그:** `get_document`,
  `search_documents` (결정 7). `ask_human`은 갭 인터뷰 모드가 자동
  부여하는 내장이라 카탈로그에 없음.
  `edit_document`는 챗봇 tool이지 Agent 장착 도구가 아님 — `get_document`/
  `search_documents`와 구분(engine.md §2).
- **장착 방식(M4 재설계)**: 기술/규칙/도구는 팔레트 정의로만 존재하며
  캔버스 독립 노드가 아니다. Agent 카드 하단 칩으로 표시. 팔레트에서
  기술/규칙/도구 항목을 Agent 카드 위로 드래그해 장착.
  공유 장착 = 여러 Agent가 같은 정의를 칩으로 참조 가능.
- 장착 데이터는 Agent `config.mounts[]{blockDefId, override?}` 배열에 저장.
  `deriveMounts`는 mount 엣지 대신 이 배열을 resolve해 기술/규칙/도구 내용을
  얻는다.
- 점선 mount 엣지와 pill 독립 노드는 M4에서 폐기됐다(schema.md edges 참조).

## 8. run 수준 규칙 (Q14 부속)

- **같은 파이프라인의 동시 run은 1개** (v1). Human 대기 중 새로
  실행하려면 기존 run을 중단해야 한다. 러너·UI 단순화 목적.
