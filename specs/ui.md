2026-07-24 grill-me 세션(Q2~Q9)으로 확정. 상위 문서:
[recruit-flow-blueprint.md](../recruit-flow-blueprint.md). 본문에서 "결정

> 상주 패널로 흡수. 유령 참조를 남기지 않는다.

## 1. 최상위 레이아웃 — IDE형 3존 (M4 전면 재설계, 결정 2)

사용자 체감은 **한 화면**. 기존 4존(상단바 / 캔버스탭·문서탭 / 사이드패널
/ 하단 채팅독)을 **3존 IDE**로 전면 교체 — 좌: 파일 탐색기, 중앙: 탭
에디터, 우: 챗봇 상주 패널.

**폐기**: `DocumentsView`(문서 탭 컴포넌트), `SidePanel`(사이드 패널 컴포넌트),
하단 채팅독(`ChatDock`) 절은 이 문서에서 더 이상 다루지 않는다. 기능은
§2(파일 탐색기) · §4(탭 에디터) · §5(챗봇 상주 패널)로 흡수됐다.

```
┌──────────────────────────────────────────────────────┐
│ 상단 바: 파이프라인 드롭다운 · Run 버튼 · 진행 표시     │
├───────────┬──────────────────────────┬───────────────┤
│ 파일       │  탭 에디터                │  챗봇         │
│ 탐색기     │  [캔버스] [문서명] [블록명]│  패널         │
│            │                          │               │
│ ▾ 블록     │  (활성 탭 컨텐츠)         │  (스레드 상주)│
│  에이전트  │                          │               │
│  자료      │                          │               │
│  완성본    │                          │               │
│  관문      │                          │               │
│  내 검토   │                          │               │
│  기술      │                          │               │
│  규칙      │                          │               │
│  도구      │                          │               │
│ ▾ 문서     │                          │               │
│ ▾ 실행기록 │                          │               │
│  (v2: 폴더)│                          │               │
└───────────┴──────────────────────────┴───────────────┘
```

- **좌: 파일 탐색기** — 블록 정의·문서·실행기록 탐색. 드래그 임포트.
- **중앙: 탭 에디터** — 캔버스 상시 고정 + 파일 열면 탭 추가/전환/닫기.
- **우: 챗봇 상주 패널** — 항상 오른쪽에 상주. 접기 가능(자동 팝업 없음).
- 파이프라인 전환/생성: 상단 바의 파이프라인 이름 클릭 → 드롭다운(목록
  + "새 파이프라인"). 캔버스와 챗봇 스레드가 함께 교체.

### 패널 리사이즈

**세 존의 모든 경계는 드래그 리사이즈**: 파일 탐색기 폭(좌·중앙 경계),
챗봇 패널 폭(중앙·우 경계), 탭 에디터 내부 분할선(예: 버전 히스토리 패널).
패널 크기는 localStorage에 보존해 재방문 시 복원.

### 라우트

| 라우트 | 내용 |
| --- | --- |
| `/pipelines/[id]` | 작업실 본체(캔버스 탭 기본). 앱 진입 시 마지막 파이프라인으로 리다이렉트 |
| `/pipelines/[id]/documents/[docId]` | 문서 탭 열림 상태 |
| `/pipelines/[id]/blocks/[blockDefId]` | 블록 정의 탭 열림 상태 |

## 2. 파일 탐색기 (좌측 패널, M4 신규, 결정 2)

평면 트리. **3구획**: ① 블록, ② 문서, ③ 실행기록. 이름 검색. **폴더 중첩은 v2.**

### 블록 구획

에이전트/자료/완성본/관문/내 검토 (실행 노드) + 기술/규칙/도구 (장착 정의) 구획.
**기술/규칙/도구는 파일 탐색기 정의 전용이며 캔버스 독립 노드가 아니다.**

```
▾ 블록
   ▾ 에이전트
      · 빈 에이전트           ← 새로 만들기용(앱 상수)
      · 이력서 작성자          ← 저장된 정의
      · 비평가
   ▸ 자료 / 완성본 / 관문 / 내 검토
   ▾ 기술
      · 비판적 읽기 기술
   ▾ 규칙
      · 수치화 강제 규칙
   ▾ 도구
      · get_document
▾ 새 블록 트레이             ← 챗봇이 add한 블록(결정 5)
```

- **파일 탐색기 임포트**: OS에서 .md·.txt 파일을 파일 탐색기 영역으로
  드래그 — 파일명(확장자 제외)이 문서 이름이 되고 내용이 v1으로 생성.
  문서 구획에 추가.
- **클릭 관용구**:
  - 구획 제목 클릭 = 펼침/접힘.
  - 항목 클릭 = 중앙 탭 에디터에서 해당 파일 탭 열기.
  - 항목 드래그(블록) = 캔버스에 추가. 참조 생성(block_def_id 연결).
    에이전트/자료/완성본/관문/내 검토 드래그 = 참조 노드 생성.
    기술/규칙/도구 드래그 = Agent 카드 위에 놓으면 장착 칩 추가.
  - 항목 더블클릭(블록) = 캔버스 빈자리 자동 배치(드래그 대안).
- **항목 우클릭 = 컨텍스트 메뉴**:

  | 항목 종류 | 메뉴 항목 |
  | --- | --- |
  | 빈 블록(blockDef 없음) | 캔버스에 추가 |
  | 저장된 정의 | 캔버스에 추가 · 이름 변경 · 삭제 |
  | 새 블록 트레이 | 승인하고 추가 · 이름 변경 · 거절(폐기) |
  | 문서 | 열기 · 이름 변경 · 삭제 |

- **새 블록 트레이 생애주기**: 챗봇 add → 트레이 입고 → 캔버스로 드래그
  = 승인(결정 5) + 라이브러리 저장 + 트레이에서 제거. 트레이에서 X =
  거절(폐기). 트레이 개수는 탐색기가 접혀도 배지 표시.
- 항목 컨텍스트 메뉴 마일스톤: M3 이후 추가.

### 문서 구획

문서 라이브러리. 항목 클릭 = 중앙 탭 에디터에 문서 편집 탭 열기.

### 실행기록 구획 (M4)

최신 run의 노드별 아티팩트 단축 접근. 항목 클릭 = 중앙 탭에 아티팩트 탭.
run 히스토리 전체 탐색은 v2.

## 3. 캔버스 — 노드·엣지 시각 언어 (Q4, M4 갱신)

### 실행 계층 (에이전트 / 자료 / 완성본 / 관문 / 내 검토)

- 카드형 노드. 좌측 핸들 = 입력, 우측 핸들 = 출력. **실선 엣지**.
- 카드 구성: 타입 아이콘 + 색 배지(헤더) / 노드 이름 / 한 줄
  요약(에이전트=역할, 관문=조건식) / 하단 상태 표시.
- 에이전트 카드 하단: 장착된 기술·규칙·도구 **칩** 표시(mounts 배열에서
  resolve). 파일 탐색기의 기술/규칙/도구 항목을 에이전트 카드 위로
  드래그해 칩 장착. 공유 장착 = 여러 에이전트가 같은 정의를 칩으로 참조.
- 관문은 마름모 느낌의 변형 카드(분기 시맨틱). 내 검토는 사람 아이콘,
  대기 시 점멸(결정 9).
- **드래그 = 참조 생성**: 파일 탐색기 블록 드래그 → block_def_id가 연결된
  참조 노드 생성. 노드 오버라이드는 인스턴스 국소, 정의 수정은 참조하는
  전 인스턴스에 반영(SSE document_changed/block_def 경유). 캔버스에서
  다듬은 노드는 우클릭 "라이브러리에 저장"으로 역승격.
- 점선 mount 엣지와 pill 독립 노드는 M4에서 폐기됐다. 기술/규칙/도구는
  캔버스 독립 노드가 아니다.

### 실행 상태 색

| 상태 | 표현 |
| --- | --- |
| 대기 | 회색 |
| 큐 대기 | 노랑 |
| 실행 중 | 파랑 — 테두리 애니메이션 + 엣지 흐름 애니메이션 |
| 성공 | 초록 |
| 실패 | 빨강 |
| 내 검토 대기 | 주황 점멸 → 우측 챗봇 패널 배지·스크롤 연결 |

과거 run 스냅샷 모드에서는 애니메이션 없이 최종 색만.

## 4. 탭 에디터 (중앙 패널, M4 재설계)

캔버스 탭은 항상 열려 있음(닫기 불가). 파일 탐색기에서 항목 열면 탭 추가.

### 탭 종류

| 탭 | 열리는 조건 | 내용 |
| --- | --- | --- |
| 캔버스 탭 | 상시 | React Flow 캔버스 + 노드·엣지 편집 |
| 문서 탭 | 파일 탐색기 문서 클릭 | 마크다운 편집기 + 버전 히스토리(접이식) |
| 블록 정의 탭 | 파일 탐색기 블록 클릭 / 캔버스 노드 클릭(참조) | 속성 폼 + 오버라이드 섹션 |
| 아티팩트 탭 | 실행 중/후 캔버스 노드 클릭 | 뷰어(실행 중 스트리밍) |

### 탭별 세부 규칙

**캔버스 탭**: 노드 클릭 시 —
- 참조 노드(`block_def_id` non-null): 중앙 탭에 **블록 정의 탭** 열기 +
  오버라이드 섹션(인스턴스 국소 변경) 표시. run 히스토리 스냅샷 모드에서는
  읽기 전용.
- run 실행 중 노드 클릭: 해당 run의 **아티팩트 탭** 열기(실시간 스트리밍).

**문서 탭**: 편집기 + 버전 히스토리(접이식 우측 패널). 버전 히스토리 폭은
드래그 리사이즈. 챗봇 `edit_document` 성공 시 새 버전 author=llm으로 추가.

**블록 정의 탭**: 속성 폼(노드 타입별). 인스턴스 노드라면 하단에 오버라이드
섹션 — 정의에서 덮어쓸 필드만 입력. 나머지는 정의값 표시.

타입별 기본/고급 속성:

| 노드 | 기본 | 고급 설정 ▾ |
| --- | --- | --- |
| 에이전트 | 이름 · 역할(시스템 프롬프트, 문서 id 포인터 삽입 지원) · 출력 형식(마크다운/JSON) · 장착된 기술/규칙/도구 목록(읽기 전용 — 장착은 파일 탐색기에서 드래그) | 모델 선택 · JSON 스키마 편집기 · 갭 인터뷰 모드(멈추고 묻기 / `[확인 필요]` 계속, 결정 9b) |
| 자료 | 문서 선택 드롭다운(문서 라이브러리 연동) | 인라인 텍스트 모드 |
| 완성본 | 템플릿 선택(1~2종) | 파일명 규칙 |
| 관문 | 조건식 편집기(예: `score >= 8`) | 실패 시 라우팅(재시도 대상 노드 / 중단) · 최대 루프 횟수 |
| 내 검토 | 지시문(사람에게 보여줄 안내) | 편집 허용 여부 |

- 편집은 **실행 중에도 허용** — run은 스냅샷(결정 9b)이라 충돌 없음.
  "다음 run에 반영됩니다" 배지만 표시.
- **자료 노드 JD 붙여넣기 (M5, 워크스트림 A-3, 사람 경로)**: 자료(Input)
  노드 정의 탭에서, 참조 중인 문서에 **새 내용을 붙여넣어 새 버전으로
  저장**하는 필드를 제공한다. 챗봇 "현재 JD" 규약(nodes.md §3)의 수동
  대응물 — documentId 재배선 없이 참조 문서 내용만 갱신하므로 다음 run이
  새 JD를 쓴다. 저장은 기존 문서 버전 API(author=human)로, "다음 run에
  반영됩니다" 배지 재사용. 인라인 텍스트 모드 노드는 이 필드가 인라인
  텍스트를 갱신.

**아티팩트 탭**: 선택한 run에서 이 노드가 낸 아티팩트.
- 마크다운 = 렌더링 뷰(원문 토글) / JSON = 구조화 뷰(점수·PASS/FAIL
  하이라이트).
- **JSON 구조화 뷰 세부 (M5, 워크스트림 B)**: 채점 아티팩트는 원문 JSON을
  그대로 던지지 않고 카드로 렌더한다. 채점 권장 스키마(nodes.md §2)의
  `total`(점수)·`verdict`(PASS/FAIL 뱃지)·`passBar`(통과선)·`blockers[]`를
  특별 취급하고, `blockers[]`는 "통과하려면 고칠 것" **실행 목록**으로
  보여준다. 권장 스키마를 벗어난 JSON은 범용 트리 뷰 + 숫자 필드 강조로
  폴백(스키마 강제 아님).
- 실행 중이면 스트리밍 실시간 추가(결정 6).
- 내 검토 노드 아티팩트는 **직접 편집 가능 + [승인] 버튼** — 챗봇 카드와
  동일 동작의 양방향 진입점.
- 루프로 한 run에서 여러 번 실행된 노드는 회차 선택 칩.
- **회차 비교 (M5, 워크스트림 B)**: 관문 루프로 여러 회차가 있으면 회차별
  점수 추이(예: 5→12)와 `blockers[]` diff를 보여준다. 데이터는 기존
  `GET /api/runs/[id]`(node_runs.iteration + artifacts)로 충분 — **신규 SSE
  이벤트·API 불필요**(engine.md §3).

### 최종 이력서 다운로드

**완성본 노드가 주 다운로드 경로 (M1부터)**: 완성본 노드 성공 시 노드
카드에 `⬇ HTML` 버튼이 나타나고, 노드 클릭 시 아티팩트 탭이
**렌더링 미리보기 + [HTML 다운로드] 버튼**을 보여준다. 챗봇 run 완료
카드의 [HTML 다운로드]는 보조 경로(M2부터). 과거 run의 이력서는 파일
탐색기 실행기록 구획 또는 캔버스 스냅샷 모드에서 완성본 노드 클릭으로 받는다.

## 5. 챗봇 상주 패널 (우측 패널, M4 재설계, 결정 2)

기존 하단 채팅 독을 **우측 세로 패널**로 이전(결정 2). 항상 오른쪽에 상주.
하단 채팅독(`ChatDock`) 컴포넌트는 폐기.

- **파이프라인당 1개 영속 스레드**(DB 저장, 새로고침 복원). 블록 제작
  대화 + run 이벤트 카드가 시간순 한 스트림(결정 9).
- 파이프라인 전환 시 챗봇 스레드도 해당 파이프라인으로 교체.
- **접기 가능**: 패널 폭을 최소화(아이콘 바 수준). 접힌 상태에서도
  내 검토 대기 배지 표시 + 내 검토 노드(캔버스 `human` 카드) 점멸 알림
  유지. **자동 팝업 없음** — 사용자가 직접 펼쳐야 한다.
- **"끄기"**: UI 숨김(백그라운드 스레드·SSE는 유지됨). "끄기"는 앱
  껐다 켜도 유지(localStorage).
- 캔버스의 점멸 내 검토 노드 클릭 → **우측 챗봇 패널을 펼치며** 해당
  카드로 스크롤(결정 9 양방향 연결).

### 메시지 타입 5종

| 타입 | 내용 |
| --- | --- |
| 사용자 텍스트 | 일반 입력. "작성해줘" = 실행 트리거(결정 9b) |
| 챗봇 응답 | 스트리밍 텍스트 |
| 블록 생성 카드 | 챗봇이 add한 블록 미리보기 + "새 블록 트레이에 담김". 카드에서 트레이 위치 하이라이트 점프 |
| 내 검토 대기 카드 | 노드 지시문 + 아티팩트 첫 줄 요약 + [탭 에디터에서 열기] / [승인]. 갭 인터뷰는 이 카드의 변형 — 질문 + 인라인 답변 입력창 |
| run 보고 카드 | run 시작/완료/실패, 관문 실패 보고(점수·사유·루프 회차). 완료 카드엔 [HTML 다운로드] |

### 마일스톤 매핑

- M1: 패널 자체를 숨김.
- M2: 챗봇 없는 **이벤트 스트림**으로 등장(run 보고·내 검토 대기 카드 —
  내 검토 노드가 M2 소속이므로).
- M3: 입력창 활성화, 사령탑 완성.

## 6. 상단 바 실행 제어 (Q8)

### Run 버튼 상태

| 상태 | 표시 |
| --- | --- |
| 대기 | `▶ 실행` — 클릭 시 그래프 검증(고아 노드·사이클·완성본 부재 경고) 후 run 시작(스냅샷 생성) |
| 실행 중 | `■ 중단` + 진행 `3/7 노드`. 중단 = 현재 노드 SDK 호출 취소, run을 `cancelled` 기록(아티팩트는 거기까지 보존) |
| 내 검토 대기 | 진행 표시가 `사람 대기 중` 주황 배지 |

### 부분 재실행 (M2)

- 노드 우클릭 → **"이 노드부터 재실행"**: 새 run 생성, 상류 아티팩트는
  **직전 완료 run에서 복사** 재사용, 해당 노드부터 하류만 실행.
- 재사용 출처 선택 UI는 v2.

## 7. 툴팁 — 전역 규칙 (Q9c)

모든 파일 탐색기 항목, 속성 필드 라벨, 상단 바 버튼에 hover 툴팁(0.5초
지연): 제목 + 2~3줄 상세 설명. UI에 설명 텍스트를 상시 노출하지 않고
툴팁으로 밀어, 화면은 직관적으로 단순하게 유지한다(§4 고급 설정 분리와
같은 원칙).
