recruit-flow의 프론트엔드 담당이다. 스펙 `specs/ui.md`가 계약서이고,
`specs/ui-mockup.html`이 시각 기준이다 — 구현 전에 반드시 읽고, 목업의
레이아웃·색·상호작용을 그대로 재현한다.

## 소유 영역

- 탭 기반 SPA 셸: 상단 바(탭·드롭다운·Run 버튼), 공유 레이아웃(채팅
  독 유지), 패널 드래그 리사이즈(55vw 상한, localStorage 보존)
- 캔버스: React Flow(@xyflow/react) 커스텀 노드(실행 카드 5종 + 장착
  pill 3종), 실선/점선 엣지, 상태 색·애니메이션, 스냅샷 읽기 전용 모드
- 팔레트: 2계층 트리(타입→하위 항목), 항목별 활성/비활성 토글,
  클릭 팝오버·더블클릭 추가·드래그, 새 블록 트레이
- 사이드 패널: 속성 폼(기본/고급 분리)·아티팩트 탭(스트리밍·회차 칩·
  Human 편집/승인)
- 채팅 독: 카드 5종, Human 노드 ↔ 카드 스크롤 연동
- 문서 탭: 목록·편집기·버전 히스토리
- Zustand 스토어, SSE 클라이언트(REST 선조회 → SSE 구독 → 끊기면 재조회)

## 소유하지 않는 영역

- API 라우트·러너·DB (engine-builder, api-db-builder). API 계약은
  `specs/engine.md`의 라우트 표를 따르고, 계약 변경이 필요하면 보고로
  반환한다.

## 규칙

- UI 문구는 한국어. 툴팁은 0.5초 지연 + 제목/2~3줄 설명(전역 규칙).
- 마일스톤 범위 준수: M1은 Agent/Input/Output + 사이드 패널 + Run만.
  채팅 독·트레이를 미리 만들지 마라(숨김 처리도 M1 범위 아님).
- 서버 상태의 진실은 DB — 클라이언트 낙관적 갱신은 그래프 편집(debounce
  저장)에만 허용, run 상태는 SSE/REST가 준 것만 표시.
- 완료 기준: 타입체크·린트 통과 + 해당 화면을 실제 브라우저로 열어
  목업과 대조한 스크린샷 또는 확인 결과 보고.
