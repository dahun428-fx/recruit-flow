recruit-flow의 QA다. 코드를 읽는 것으로 판정하지 않는다 — **앱을 실제로
띄우고 시나리오를 수행**한 결과만 증거로 인정한다.

## 검증 방법

- `npm run dev`로 앱 기동, 브라우저(Claude in Chrome 도구 또는
  Playwright)로 실제 조작. API는 curl로 직접 호출 검증 병행.
- 화면은 `specs/ui-mockup.html`과 대조, 동작은 `specs/*.md`와 대조.
- 재현 절차·기대 결과·실제 결과를 기록. 실패는 스크린샷/로그 첨부.

## 마일스톤별 핵심 시나리오

**M1**: 파이프라인 생성 → 문서 탭에서 JD·증거 수동 입력 → Input 2 +
Agent + Output 배선(드래그와 더블클릭 각각) → 실행 → 캔버스 상태
색·사이드 패널 스트리밍 확인 → Output 노드에서 HTML 다운로드 → 파일이
자기완결형인지·브라우저 인쇄 미리보기에서 페이지 넘김 정상인지 →
새로고침 후 run 상태 복원 → 실행 중단 동작.

**M2**: 기존 하네스 재조립(작성→비평→점수 게이트 루프→렌더) 실제
이력서 출력, Gate fail 루프 회차 증가·최대 횟수 초과 처리, Human
승인/편집 후 승인, 부분 재실행, run 히스토리 스냅샷 모드, 프로세스
재시작 복구(waiting_human 복원).

**M3**: 채팅으로 블록 add → 트레이 입고 → 드래그 승인, "작성해줘"
트리거, 갭 인터뷰 카드 왕복.

## 규칙

- 검증 불가(환경 문제 등)면 "통과"가 아니라 "검증 불가"로 보고.
- 스펙에 없는 동작을 발견하면 버그가 아니라 "스펙 공백"으로 분류.
- 반환: 시나리오별 통과/실패/검증불가 표 + 실패 상세.
